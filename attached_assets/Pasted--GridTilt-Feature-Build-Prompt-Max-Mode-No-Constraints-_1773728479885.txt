## SECTION 1: SUPPLY CHAIN TRACKER — NEW HEADLINE FEATURE

This is GridTilt's next major feature. It replaces the Thesis Calculator in the nav (keep the calculator accessible via a link but it's no longer a primary nav item). The Supply Chain Tracker visualizes how power flows from raw materials to the GPU. It's the visual storytelling feature that makes GridTilt unique.

### 1A. Concept

An interactive, animated flow diagram showing the AI power supply chain as connected nodes:

```
RAW MATERIALS → GENERATION → TRANSMISSION → DISTRIBUTION → END USE
(uranium, gas,   (nuclear,     (transformers,  (switchgear,    (data centers,
 copper, steel,   gas turbines,  HV cables,      substations,    hyperscalers,
 rare earth)      solar, wind)   transmission     power mgmt)     AI compute)
                                 lines)
```

Each stage is a visual node/column. Lines/arrows flow between them showing the supply chain connections. The whole thing should feel like an interactive infographic, not a static chart.

### 1B. Visual Design

**Layout:** Horizontal flow, left to right, filling the main content area. On mobile, it can stack vertically or scroll horizontally.

**Each stage (node) should display:**
- Stage name (large, bold): "Raw Materials", "Generation", "Transmission", "Distribution", "End Use"
- A one-line tagline: "Where it comes from", "How it's made", "How it moves", "How it connects", "Where it goes"
- Number of tracked companies in this stage
- Aggregate sector performance today (green/red percentage)
- A bottleneck indicator: a small badge showing the current constraint level for this stage. Use a simple 3-level system:
  - Green: "Flowing" (no major constraint)
  - Orange: "Tightening" (lead times growing, demand outpacing supply)
  - Red: "Bottlenecked" (multi-year backlogs, critical shortage)
- For now, hardcode the bottleneck status per stage. I'll update them manually. Make it easy to change (a simple config object or JSON file).

**Flow lines between stages:**
- Animated dashed lines or flowing particle effects connecting the stages left to right
- The lines should pulse subtly to feel alive
- Line thickness or color could reflect flow health (green = healthy, orange = constrained)
- Use CSS animations or a lightweight canvas/SVG approach. No heavy libraries.

**Color scheme:**
- Match GridTilt's dark theme
- Each stage could have a subtle colored accent/glow: copper/brown for Raw Materials, orange for Generation, blue for Transmission, green for Distribution, purple for End Use
- Or keep them all in the GridTilt orange family. Use your judgment on what looks best.

### 1C. Interaction — Expanding a Stage

Clicking (or hovering on desktop) a stage node expands it to reveal the companies inside. This is the key interaction.

**Expanded view shows:**
- All companies tracked in this stage, displayed as compact stock cards (ticker, price, daily change %)
- The bottleneck detail: a 2-3 sentence explanation of the current constraint at this stage. Examples:
  - Raw Materials: "Copper prices above $14,000/ton. Uranium spot at $93/lb. Electrical steel lead times at 8-12 months. Demand from AI data centers could require 475,000 additional tons of copper annually by 2026."
  - Transmission: "Large power transformer lead times at 18-36 months. US domestic production ~60 units/year against estimated demand of 200-500 over 5 years. This is the tightest bottleneck in the chain."
  - End Use: "48 tracked facilities. 28 operational, 15 under construction, 5 announced. Total tracked capacity: 20.7 GW."
- Key metric for this stage: a single headline number that captures the bottleneck. Examples:
  - Raw Materials: "Copper: $14,200/ton" or "Uranium: $93/lb"
  - Generation: "GE Vernova backlog: $200B+"
  - Transmission: "Transformer lead time: 18-36 months"
  - Distribution: "Eaton order backlog: 2-3 years"
  - End Use: "48 facilities / 20.7 GW tracked"

**Hardcode these bottleneck descriptions and metrics for now.** Put them in a config file (`supply-chain-config.json` or similar) that I can easily edit. The key metrics can be updated to pull from live data later.

**Clicking a stock card within an expanded stage** should link to the `/stock/[ticker]` page.

## SECTION 4: EMAIL CAPTURE AND AUTOMATED NEWSLETTER

### 4A. Email Capture — Use Resend

Implement email capture using Resend (resend.com). Free tier: 3,000 emails/month, more than enough to start.

**Backend:**
- Create an API route: `POST /api/subscribe` that accepts `{ email: string }`
- Validate email format server-side
- Store emails in a database table (or a JSON file if no DB — whatever the current stack supports)
- Also add the email to a Resend audience via their API (for later sending)
- Handle duplicates gracefully: return success message "You're already subscribed" instead of an error
- Rate limit: max 5 subscribe attempts per IP per hour

**Placements (3 locations):**

1. **Bottom of Tilt Overview** — after the Sector Pulse section, a full-width bar:
   - Left side: "Get the GridTilt Brief. Thesis health, top movers, new facilities. One email per month."
   - Right side: email input + "Subscribe" button
   - Style: subtle background (slightly lighter than page bg), orange accent on the button

2. **Scroll-triggered banner** — appears after user scrolls 70% down any page:
   - Small bar that slides up from the bottom (not a popup/modal that blocks content)
   - Same copy and input
   - Dismissible with X. Once dismissed, don't show again for 7 days (use localStorage)
   - On mobile: make sure it doesn't block map interaction or nav

3. **Dedicated /subscribe page** — for linking from X bio, LinkedIn posts:
   - Clean page with headline, 3 value props, email input, subscribe button
   - "The GridTilt Brief: thesis health check, top movers, new facilities, one data insight. Monthly. No spam."
   - Success state: "You're in. First brief arrives next month." with a checkmark
   - This becomes the CTA landing page for all content marketing

**Success/error states:**
- Success: input clears, green checkmark, "You're in"
- Already subscribed: "You're already on the list"
- Invalid email: "That doesn't look like an email" (client-side validation first)
- Error: "Something went wrong, try again"

**Environment variable needed:** `RESEND_API_KEY` — leave a clear comment explaining where to get this (resend.com dashboard) and where to set it.

### 4B. Monthly Newsletter — GridTilt Brief

Build the infrastructure for a monthly automated email. This uses the `/api/export/weekly` endpoint (repurposed for monthly) and Resend's sending API.

**Email template:**
Build an HTML email template that matches GridTilt's brand (dark background, orange accents, clean typography). The template should include:

1. **Header:** GridTilt logo + "The GridTilt Brief — [Month Year]"
2. **Thesis Health:** The 3 index values + thesis status (Expanding/Stable/Cooling), with colored indicators
3. **Top Movers This Month:** Top 5 stocks by monthly % change with ticker, name, sector, and change
4. **Sector Pulse:** Which sectors outperformed/underperformed this month
5. **Power Map Update:** New facilities added this month (if any), total count
6. **New on GridTilt:** Brief mention of any new features shipped
7. **One Insight:** A placeholder section where I can manually add a 2-3 sentence data observation
8. **CTA:** "Explore the full dashboard at gridtilt.com"
9. **Footer:** "You're receiving this because you subscribed at gridtilt.com. Unsubscribe: [link]"

**Sending mechanism:**
- Create an API route: `POST /api/newsletter/send` (protected, requires auth or a secret key)
- This route:
  1. Calls `/api/export/daily` to get current data
  2. Populates the email template with the data
  3. Sends to all subscribers via Resend's batch send API
  4. Logs the send (date, subscriber count, any errors)

- Also create `GET /api/newsletter/preview` that returns the rendered HTML template with current data so I can preview the email before sending

**Unsubscribe:**
- Each email includes an unsubscribe link: `gridtilt.com/unsubscribe?token=[hashed_email]`
- Clicking it removes the email from the subscriber list and shows a confirmation page
- This is legally required (CAN-SPAM)

### 4C. Subscriber Admin

Build a simple protected page at `/admin/subscribers` (protect with a secret key in the URL or a simple password) that shows:
- Total subscriber count
- List of emails with subscribe date
- A "Send Newsletter" button that triggers `/api/newsletter/send`
- A "Preview Newsletter" button that opens the preview
- Ability to remove individual subscribers
