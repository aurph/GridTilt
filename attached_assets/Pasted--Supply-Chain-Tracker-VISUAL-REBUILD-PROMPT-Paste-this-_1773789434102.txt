## WHAT THIS IS (READ THIS FIRST)

The Supply Chain Tracker is an **interactive flow diagram**. NOT a screener. NOT a table. NOT a list of stocks grouped by category. It is a VISUAL, ANIMATED, EDUCATIONAL diagram that shows how power flows from raw materials to GPUs. Think: an interactive infographic you'd see on Bloomberg or the New York Times data team. Think: a Sankey diagram meets an animated system architecture diagram.

If the end result looks like a stock screener with category headers, you have built the wrong thing. The stocks are INSIDE the diagram nodes — they are revealed on interaction, not displayed by default.

---

## RENDERING APPROACH

Use **React Flow** (`@xyflow/react`, formerly `reactflow`). Install it:

```
npm install @xyflow/react
```

React Flow gives us: draggable nodes, animated edges, zoom/pan, custom node rendering, and edge animations — all out of the box. This is the foundation.

If React Flow causes conflicts with the existing stack, fall back to **custom SVG rendering** using inline `<svg>` elements with React. Do NOT fall back to a table or card grid. The output MUST be a node-and-edge diagram.

## LAYOUT — THE FLOW DIAGRAM

### Structure

5 stage nodes arranged **horizontally left-to-right** in a pipeline:

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│             │    │             │    │             │    │             │    │             │
│    RAW      │───▶│  GENERATION │───▶│ TRANSMISSION│───▶│ DISTRIBUTION│───▶│   END USE   │
│  MATERIALS  │    │             │    │             │    │             │    │             │
│             │    │             │    │             │    │             │    │             │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
```

This is the default view. 5 nodes. 4 connecting edges. That's it. Clean.

### Node Positioning (React Flow coordinates)

```javascript
const stagePositions = [

  { id: 'generation',     position: { x: 350,  y: 200 } },
```

Adjust x-spacing so all 5 fit within the viewport on a 1440px screen with ~40px padding on each side. On smaller screens, allow horizontal scroll/pan (React Flow handles this).

### Viewport

The diagram container should be **full width of the content area** and **at least 70vh tall** (minimum 500px). Give React Flow's `<ReactFlow>` component `fitView` prop so it auto-fits the 5 nodes on load. Enable `panOnDrag`, `zoomOnScroll`, and `zoomOnPinch` for mobile.

Background: use React Flow's `<Background>` component with `variant="dots"`, color `#333`, gap `20`, size `1`. This gives a subtle dot grid on the dark background — looks technical and clean.

Create a custom React Flow node component called `StageNode`. Each node renders as a **card** (NOT a default React Flow node). The card is the main visual unit of the diagram.

### Bottleneck Indicator Bar

Inside each node, render a small horizontal progress-style bar that visually shows the constraint level:

- **Flowing** (green): bar is mostly filled, `#22C55E`, label "Flowing"
- **Tightening** (orange): bar is ~60% filled, `#F0A500`, label "Tightening"
- **Bottlenecked** (red): bar is nearly full, `#EF4444`, label "Bottlenecked"

The bar should be 100% width of the card interior, 6px tall, rounded, with a dark track behind it (`#2A2A3E`). The fill portion uses the status color. The label sits to the right of the bar or below it.

### Stage Icons

Each stage gets a small icon (use Lucide React icons since they're already in the stack):

- Raw Materials: `<Pickaxe />` or `<Mountain />`
- Generation: `<Zap />` or `<Factory />`
- Transmission: `<Cable />` or `<ArrowRightLeft />`
- Distribution: `<Network />` or `<GitBranch />`
- End Use: `<Server />` or `<Cpu />`

Icon: 18px, placed inline with the stage name, colored with the stage's accent color.

## CONNECTING EDGES — ANIMATED FLOW LINES

This is what makes it feel like a flow diagram instead of 5 cards sitting next to each other. The edges are critical.

### Edge Configuration

4 edges connecting the stages left to right:

```javascript
const edges = [
  { id: 'e1', source: 'raw-materials', target: 'generation',   animated: true },
  { id: 'e2', source: 'generation',    target: 'transmission', animated: true },
  { id: 'e3', source: 'transmission',  target: 'distribution', animated: true },
  { id: 'e4', source: 'distribution',  target: 'end-use',      animated: true },
];
```

### Edge Styling

React Flow's `animated: true` gives a basic marching-ants dashed line. Enhance it:

```javascript
const edgeStyle = {
  stroke: 'rgba(240, 120, 0, 0.4)',  // GridTilt orange, semi-transparent
  strokeWidth: 2,
};
```

Use `type: 'smoothstep'` for the edges so they curve slightly — looks more polished than straight lines.

### Custom Animated Edge (if React Flow's default animation isn't impressive enough)

Create a custom edge component that renders an SVG path with **flowing dots/particles** along it:

```jsx
// Render 3 small circles that travel along the edge path using CSS animation
// Each dot is 4px, orange (#F07800), 60% opacity
// Animation: move along the path over 3 seconds, staggered start times
// Use SVG <animateMotion> or CSS offset-path
```

The flowing particles represent power/energy flowing through the supply chain. This is the visual metaphor that makes the feature memorable.

### Edge Color by Health

Optionally, color each edge segment based on the bottleneck status of the TARGET stage:

- Edge into a "Flowing" stage: greenish tint
- Edge into a "Tightening" stage: orange (default)
- Edge into a "Bottlenecked" stage: reddish tint, slightly thicker (3px)

This lets users instantly see where the chain is stressed just by looking at the edge colors.

## EXPANDED STATE — CLICKING A STAGE NODE

When a user clicks a stage node, it EXPANDS to reveal the companies and educational content inside. This is the core interaction.

### How Expansion Works

**Option A (preferred): The node itself grows.**

When clicked, the node smoothly animates from 260px wide / ~180px tall to **400px wide / auto height** (enough to fit the expanded content). The other nodes shift to make room (React Flow handles repositioning if you update the node data). Transition: 400ms ease-out.

**Option B (fallback): A detail panel slides in.**

If expanding the node in-place causes layout issues, instead show a **slide-in panel** below the flow diagram (or to the right on wide screens) that contains the expanded content. The clicked node gets a highlighted border (orange) and the panel shows its details. The flow diagram stays intact above.

Either way: the flow diagram with its animated edges MUST remain visible at all times. The expanded content supplements it, never replaces it.

### Expanded Content — 3 Sections Inside Each Stage

#### Section A: Educational Context (THE LEARNING COMPONENT)

This is what makes users UNDERSTAND the supply chain, not just see stock tickers.

A 3-5 sentence paragraph explaining what this stage does, why it matters, and what the current situation is. Written in plain English, not financial jargon.

Example for Transmission:
> "After electricity is generated, it needs to travel hundreds of miles to reach data centers. That requires high-voltage transmission lines and large power transformers — and this is where the AI power buildout hits its tightest bottleneck. The US manufactures roughly 60 large power transformers per year, but the AI buildout alone could require 200-500 over the next five years. Lead times have stretched to 18-36 months, and companies in this stage have multi-year order backlogs with significant pricing power."

**Styling:** 13px, line-height 1.6, color #ccc, max-width 360px. A subtle left border in the stage's accent color (3px, 30% opacity).

Hardcode these descriptions. Put them in a config file. I will refine them later.

#### Section B: Key Metrics (2-3 headline numbers)

Displayed as large stat blocks:

```
┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
│  18-36 months   │  │  ~60/year       │  │  200-500        │
│  Transformer    │  │  US LPT         │  │  Needed over    │
│  lead time      │  │  production     │  │  next 5 years   │
└─────────────────┘  └─────────────────┘  └─────────────────┘
```

- Number: 20px, bold, white
- Label: 11px, #888, 2 lines max
- Card: dark background (#222238), 8px border-radius, 12px padding
- Arrange horizontally, wrap if needed

Hardcode these metrics per stage.

#### Section C: Companies (stock cards, scrollable)

The tracked companies in this stage, displayed as **compact stock mini-cards** in a grid (2-3 columns):

```
┌───────────────────┐
│  CCJ    ▲ +2.3%   │
│  Cameco Corp      │
│  Uranium mining   │
└───────────────────┘
```

- Ticker: 13px, bold, white
- Daily change: 12px, green (#22C55E) or red (#EF4444)
- Company name: 11px, #888
- Sub-category: 10px, #666
- Card: `#1E1E32` background, 6px border-radius, 8px padding
- On hover: subtle border glow in stage accent color
- On click: navigate to `/stock/[ticker]`

If a stage has 15+ companies, show the first 8-10 and add a "Show all X companies ▼" toggle. Don't overwhelm with a massive list.

### Close/Collapse

Clicking the expanded node again (or clicking a "✕ Close" button in the expanded view, or clicking a different stage) collapses it back to default size. Smooth transition.

When this is done, the Supply Chain page should look like:

- A dark canvas with a subtle dot grid background
- 5 card-shaped nodes arranged left to right (or top to bottom on mobile)
- Glowing orange animated connection lines flowing between the nodes with particles moving along them
- Each node shows: stage name, tagline, bottleneck bar, company count, key metric
- Clicking a node expands it to reveal: educational paragraph, key stat blocks, and a grid of stock mini-cards

If someone screenshots this feature, it should be immediately obvious that it's a FLOW DIAGRAM showing connected stages, not a list.

## DO NOT

- Do NOT render this as a table or flat card grid
- Do NOT show all stock tickers visible by default — they're revealed on click
- Do NOT use a basic HTML layout with flexbox for the stage arrangement — use React Flow (or SVG) so there are actual drawn connection lines between nodes
- Do NOT skip the animated edges — they are the single most important visual element
- Do NOT make the expanded state replace the diagram — the diagram stays visible
- Do NOT use heavy libraries beyond React Flow (no D3 Sankey, no vis.js, no cytoscape)
- Do NOT build a screener and call it a tracker
