# Supply Chain Tracker V4 — Connected Network Graph

Tear out the current Supply Chain Tracker and rebuild it. The current version lays out icons in a grid with no connections between them. That's not a supply chain — it's a categorized icon menu. The entire point of this feature is the CONNECTIONS between nodes showing how materials, components, and power flow through the system.

---

## THE CONCEPT

This is a **network graph**. Nodes are sub-systems (Uranium, Copper, Nuclear, Transformers, Cooling, Hyperscalers, etc.). Lines connect nodes that have a real supply relationship. You look at this and you can TRACE the path:

- Uranium → Nuclear (uranium fuels nuclear plants)
- Copper → Transformers (transformers need copper windings)
- Copper → HV Cable (cables are copper)
- Steel → Transformers (transformer cores are electrical steel)
- Steel → Line Construction (transmission towers are steel)
- Nuclear → Transformers (nuclear output needs step-up transformers)
- Gas Turbines → Transformers (same — generation connects to transmission)
- Transformers → Switchgear (power flows from transmission into distribution)
- Switchgear → Cooling (distribution feeds the data center systems)
- Cooling → Hyperscalers (cooling keeps their GPUs running)
- DC Construction → Hyperscalers (someone builds their facilities)
- Hyperscalers → Compute (they buy the chips)

That's a WEB. Not a grid. Not a list. A web of connections you can explore.

---

## TECHNICAL APPROACH

Use **D3-force** layout for the network graph. D3's force simulation positions nodes organically based on their connections while keeping the general left-to-right flow (raw materials on the left, end use on the right).

```
npm install d3
```

Render the graph in a single `<svg>` element that fills the content area. D3 handles: node positioning via force simulation, link rendering as SVG `<line>` or `<path>` elements, zoom/pan, and dragging nodes.

### Why D3-force:
- Nodes position themselves based on connections — connected nodes cluster together naturally
- The layout is organic and web-like, not grid-rigid
- SVG rendering means lines between nodes are first-class elements, not afterthoughts
- It handles any number of nodes and connections gracefully
- Pan + zoom works on all screen sizes

### Fallback:
If D3 causes issues, use a custom SVG with manually positioned nodes (see the coordinate map below). But TRY D3 first — the force simulation is what makes this feel alive.

## D3 FORCE LAYOUT

### Force Simulation Setup

```typescript
import * as d3 from 'd3';

const simulation = d3.forceSimulation(nodes)
  // Push nodes left-to-right based on their stage
  .force('x', d3.forceX(d => {
    // stageIndex 0-4 maps to x positions across the viewport
    const stageX = [0.1, 0.3, 0.5, 0.7, 0.9]; // as fraction of width
    return stageX[d.stageIndex] * viewportWidth;
  }).strength(0.8))  // strong — keeps stages in columns

  // Spread nodes vertically within each stage
  .force('y', d3.forceY(viewportHeight / 2).strength(0.05))

  // Prevent node overlap
  .force('collide', d3.forceCollide(65))

  // Pull connected nodes slightly closer
  .force('link', d3.forceLink(links).id(d => d.id).distance(150).strength(0.3))

  // Light repulsion so nodes don't stack
  .force('charge', d3.forceManyBody().strength(-200));
```

### What this produces:

Nodes cluster into 5 vertical columns (one per stage) from left to right. Within each column, nodes spread vertically. Connected nodes pull slightly toward each other, so you see the clustering — Transformers sits between Generation and Distribution with many lines converging on it. The graph is organic, not grid-rigid.

### Important force settings:
- The `forceX` with high strength (0.8) keeps the left-to-right stage flow. Without this, nodes would jumble.
- `forceCollide(65)` prevents overlap — each node needs ~60px radius of space.
- `forceLink.distance(150)` keeps connected nodes at a readable distance.
- Let the simulation run ~300 ticks on init, then freeze positions. Don't keep it running continuously (causes jitter).

## INTERACTION — CLICKING A NODE

### What happens when you click a node:

1. **That node's circle glows** (active state — colored stroke + drop shadow)
2. **All connections TO and FROM that node highlight** (brighter, thicker)
3. **All connected nodes also glow slightly** (their circles get a subtle colored stroke)
4. **Everything else dims** — unconnected nodes and links fade to 15-20% opacity
5. **A detail panel appears** — either below the SVG or as a right-side panel

This is the key interaction. You click "Transformers" and you instantly SEE: connections coming IN from Copper, Steel, Nuclear, Gas Turbines, Solar, SMRs... and connections going OUT to Switchgear and Power Mgmt. The visual web highlights the path. THAT'S the educational moment.

## ZOOM AND PAN

Enable D3 zoom behavior on the SVG:

```typescript
const zoom = d3.zoom()
  .scaleExtent([0.5, 3])
  .on('zoom', (event) => {
    svgContent.attr('transform', event.transform);
  });

svg.call(zoom);
```

- Scroll to zoom, drag to pan
- Double-click to reset view
- On load, auto-fit all nodes in the viewport

### Mobile:
- Pinch to zoom, drag to pan (same D3 zoom handles touch events)
- Nodes may need to be slightly larger (radius 38) for tap targets
- Detail panel goes full-width below the graph

## INITIAL ANIMATION

On page load:
1. Nodes fade in by stage, left to right (0ms, 100ms, 200ms, 300ms, 400ms per stage)
2. Connection lines draw in after all nodes are visible (500ms, staggered by stage distance)
3. Lines use SVG `stroke-dashoffset` animation to "draw" from source to target

```css
.supply-link {
  stroke-dasharray: 1000;
  stroke-dashoffset: 1000;
  animation: drawLine 0.8s ease-out forwards;
}

@keyframes drawLine {
  to { stroke-dashoffset: 0; }
}
```

Stagger the line draw animations so shorter links (within a stage) draw first, longer links (cross-stage) draw last. The effect: the network assembles itself in front of you, left to right.

## RESPONSIVE BEHAVIOR

**1440px+:** Full graph, comfortable spacing, detail panel on the right side
**1024-1439px:** Full graph, tighter spacing, detail panel below
**768-1023px:** Graph takes full width, nodes slightly smaller (radius 26), detail panel below
**<768px:** Graph takes full width, pinch/zoom enabled, nodes radius 28 for touch, detail panel below full-width

The D3 force layout + SVG viewBox handles most of this automatically. Set the `viewBox` to match the actual content bounds after simulation settles, and the SVG scales to fit any container width.

## DO NOT

- Do NOT lay out nodes in a rigid grid — use D3 force simulation for organic positioning
- Do NOT render nodes without connection lines — THE LINES ARE THE FEATURE
- Do NOT use straight lines — use `d3.linkHorizontal()` bezier curves
- Do NOT skip the highlight-on-click interaction — dimming unrelated nodes and brightening connected ones is the core UX
- Do NOT skip "RECEIVES FROM" / "FEEDS INTO" in the detail panel — this is how users learn
- Do NOT use any blue colors — all node colors in the warm orange/copper/gold/amber family
- Do NOT make the detail panel a modal — it's inline, below or beside the graph
- Do NOT show company tickers in the default view — they appear only in the detail panel on click
- Do NOT keep the force simulation running after initial layout settles — freeze it after ~300 ticks to prevent jitter
