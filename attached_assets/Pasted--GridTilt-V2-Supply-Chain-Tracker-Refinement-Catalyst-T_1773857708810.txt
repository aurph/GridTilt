# PART 1: SUPPLY CHAIN TRACKER — VISUAL REFINEMENT

The Supply Chain Tracker exists and has the right foundation (React Flow, 5 nodes, animated edges, summary bar). But it has major problems:

1. **The nodes are tiny cards floating in a massive empty void.** 70%+ of the screen is blank dot grid. The feature should FILL the viewport.
2. **It's not educational.** A user looking at this learns nothing about the AI power supply chain. There's no visible explanation text, no context, no "why should I care" content.
3. **The connection lines are underwhelming.** Small dots on a thin line don't communicate "power flowing through a supply chain."
4. **There's no verticality.** Everything sits on one thin horizontal band in the middle of the screen. The page feels empty.
5. **There's not enough imagery/iconography.** The stage icons are tiny. There are no illustrations, no visual metaphors, nothing that makes this feel like an infographic.

Here's exactly what to change:

---

## 1A. KILL THE EMPTY CANVAS — FILL THE VIEWPORT

**Remove React Flow's pan/zoom/drag behavior.** This is not a node editor — it's an infographic. Users should scroll the page normally, not drag a canvas around. The dot grid background taking up 70% of the screen is useless whitespace.

**Replace the React Flow canvas** with a normal scrollable page layout. Keep the visual connection lines between stages (draw them with SVG overlays), but lay out the content using standard CSS grid/flexbox so it fills the screen naturally.

If you must keep React Flow, then at minimum:
- Set `panOnDrag={false}`, `zoomOnScroll={false}`, `zoomOnPinch={false}`
- Remove the `<Background>` dot grid entirely — use the standard page background (`#0A0A1A` or whatever the app uses)
- Make the nodes MUCH larger (see below)
- Set `fitView` with generous padding so nodes fill the available space

But honestly: **rip out React Flow and use a normal page layout with SVG connection lines.** React Flow was meant to prevent a screener — mission accomplished, you built nodes and edges. But now the canvas behavior is hurting the UX. A scrollable infographic page is better.

---

### The Stagger Pattern

The 5 stage cards **alternate left and right** as you scroll down the page, connected by diagonal SVG lines:

- **Stage 1 (Raw Materials):** Left-aligned, ~60% page width
- **Stage 2 (Generation):** Right-aligned, ~55% page width
- **Stage 3 (Transmission):** Left-aligned, ~60% page width
- **Stage 4 (Distribution):** Right-aligned, ~55% page width
- **Stage 5 (End Use):** Centered, ~65% page width

Each card is vertically spaced ~80-120px from the next. Between each pair, an **SVG diagonal line** (or curved bezier path) connects them, with the animated flowing dots along the path. The lines go from the bottom-right of a left-aligned card to the top-left of the next right-aligned card, creating a zigzag flow down the page.

### Why This Works

- **Fills the viewport** — no empty canvas, content flows naturally as you scroll
- **Creates verticality** — the page has depth, you scroll through the supply chain
- **The zigzag path IS the flow** — you can see power moving from stage to stage down the page
- **Each card is big enough to show educational content** by default, not just a cramped mini-card
- **Feels like an infographic** — like scrolling through a Bloomberg feature piece

## 1D. CONNECTION LINES — SVG OVERLAY

Since we're switching from React Flow canvas to a normal page layout, draw the connection lines as an **absolutely positioned SVG overlay** that sits on top of the page content.

```tsx
// ConnectionLines.tsx
// Renders an <svg> element covering the full scroll height of the Supply Chain page
// For each pair of adjacent stages, draws a bezier curve from the bottom of one card to the top of the next
// Use refs on each stage card to get their positions, recalculate on resize

const ConnectionLines = ({ stageRefs }) => {
  // Get bounding rects of each stage card
  // Draw SVG <path> bezier curves connecting them
  // Animate flowing dots along each path

  return (
    <svg className="connection-overlay" style={{
      position: 'absolute',
      top: 0,
      left: 0,
      width: '100%',
      height: '100%',
      pointerEvents: 'none',
      zIndex: 1,
    }}>
      {paths.map((path, i) => (
        <g key={i}>
          {/* The line itself */}
          <path
            d={path.d}
            stroke={path.color}
            strokeWidth={2.5}
            fill="none"
            strokeDasharray="8 4"
            opacity={0.3}
          />
          {/* Animated flowing dots */}
          <circle r="4" fill={path.color} opacity={0.7}>
            <animateMotion
              dur="3s"
              repeatCount="indefinite"
              path={path.d}
            />
          </circle>
          <circle r="3" fill={path.color} opacity={0.5}>
            <animateMotion
              dur="3s"
              repeatCount="indefinite"
              path={path.d}
              begin="1s"
            />
          </circle>
          <circle r="3" fill={path.color} opacity={0.5}>
            <animateMotion
              dur="3s"
              repeatCount="indefinite"
              path={path.d}
              begin="2s"
            />
          </circle>
        </g>
      ))}
    </svg>
  );
};
```

The bezier curves should be smooth S-curves going from one card to the next. Color each connection based on the bottleneck status of the target stage (green/orange/red tint, same as before).

**Make the lines thicker (2.5px) and the dots bigger (4px)** than what's currently there. The current dots are barely visible.

## 2A. API-DRIVEN EARNINGS CALENDAR

Earnings dates must be **automatically fetched from an API**, not hardcoded.

### Primary API: Finnhub

```
npm install finnhub
```

**Endpoint:** `GET https://finnhub.io/api/v1/calendar/earnings`

**Parameters:**
- `from` — start date (YYYY-MM-DD)
- `to` — end date (YYYY-MM-DD)
- `token` — API key (store in env as `FINNHUB_API_KEY`)

**Free tier:** 60 requests/minute, no daily limit, JSON format.
**Sign up at:** https://finnhub.io/

### Backup: Alpha Vantage

```
GET https://www.alphavantage.co/query?function=EARNINGS_CALENDAR&horizon=3month&apikey=YOUR_KEY
```

Returns CSV. Free tier: 500 req/day. Store as `ALPHA_VANTAGE_API_KEY`.

### Server-Side Fetcher

```typescript
// server/earnings.ts

interface EarningsEntry {
  ticker: string;
  company: string;
  date: string;           // YYYY-MM-DD
  time: 'BMO' | 'AMC' | 'TBD';
  quarter: string;        // "Q1 2026"
  estimatedEPS: number | null;
  confirmed: boolean;
  sector: string;
  supplyChainStage: string;
}

// On server start + every 6 hours:
// 1. Fetch Finnhub earnings calendar for next 90 days
// 2. Filter to our tracked tickers (see full list below)
// 3. Cache in memory
// 4. Serve via GET /api/catalysts/earnings

// Finnhub returns ALL earnings in a date range — filter client-side
// This means ONE API call covers all 100+ tickers

async function fetchEarningsCalendar(): Promise<EarningsEntry[]> {
  const today = new Date();
  const future = new Date(today);
  future.setMonth(future.getMonth() + 3);

  const res = await fetch(
    `https://finnhub.io/api/v1/calendar/earnings?from=${fmt(today)}&to=${fmt(future)}&token=${process.env.FINNHUB_API_KEY}`
  );
  const data = await res.json();
  const tracked = getAllTrackedTickers();

  return data.earningsCalendar
    .filter(e => tracked.includes(e.symbol))
    .map(e => ({
      ticker: e.symbol,
      company: getCompanyName(e.symbol),
      date: e.date,
      time: e.hour === 'bmo' ? 'BMO' : e.hour === 'amc' ? 'AMC' : 'TBD',
      quarter: `Q${e.quarter} ${e.year}`,
      estimatedEPS: e.epsEstimate,
      confirmed: true,
      sector: getSector(e.symbol),
      supplyChainStage: getStage(e.symbol),
    }));
}
```
