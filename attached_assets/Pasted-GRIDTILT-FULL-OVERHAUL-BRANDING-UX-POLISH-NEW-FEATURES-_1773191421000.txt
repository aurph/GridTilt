SECTION 1: BRANDING & VISUAL IDENTITY TIGHTENING
The current design works but needs tightening to feel more cohesive and intentional. The goal is: dark, data-dense, trustworthy, fast. Think Bloomberg Terminal meets a modern SaaS dashboard. Not playful, not startup-y. Professional and information-dense.
1.1 Color System Audit & Lock
Review every color currently used across the entire app. Then standardize to a strict palette:

Primary background: The current dark background is good. Lock it in. Make sure it's consistent across every page/tool — no slight variations between pages.
Secondary background: For cards, panels, sidebars. Should be a slightly lighter shade of the primary. Consistent everywhere.
Accent color (orange): GridTilt's orange should be THE accent. Use it for: active states, selected tabs, key data highlights, the news banner (Section 5), hover states, and primary CTAs. Define one exact hex value and use it everywhere. No close-but-not-quite oranges on different pages.
Text hierarchy:

Primary text (headings, key numbers): White or near-white
Secondary text (labels, descriptions): A muted gray that's clearly readable but not competing with primary text
Tertiary text (timestamps, footnotes): Even more muted


Positive/negative indicators: Green for up/positive. Red for down/negative. Use the same exact green and red everywhere — stock prices, index movements, grid stress indicators. No mixing of shades.
Borders and dividers: Subtle. Very subtle. Use opacity-based borders (like rgba(255,255,255,0.08)) rather than solid colors. The grid lines should organize content without being visible design elements.

Audit every single page and component. Fix any color inconsistencies. I want someone to be able to screenshot any part of GridTilt and it looks like it belongs to the same product.
1.2 Typography Tightening

Lock in a single font stack for the entire app. Whatever we're using now, make sure it's consistent. No mixing.
Numbers should use a tabular/monospace variant or font-feature-settings so columns of numbers align properly. This matters a lot on The Stack and Tilt Overview.
Establish a clear type scale: page titles, section headers, card headers, body text, labels, small text. Use it consistently. No arbitrary font sizes.

1.3 Spacing & Layout Consistency

Define a spacing unit (8px base recommended) and use multiples of it everywhere. Padding inside cards, margins between sections, gaps in grids — all should be multiples of the base unit.
Every card/panel should have the same border-radius, the same internal padding, the same shadow treatment (if any). No card-by-card variations.
Page-level layout should have consistent left/right margins and max-width across all tools.

1.4 Logo & Header Polish

The "GridTilt" wordmark in the header/nav should be clean and recognizable. If it's just text, make sure it's properly weighted and spaced.
Navigation between the five tools (Tilt Overview, The Stack, Power Map, Thesis Calculator, Portfolio Overlay) should be crystal clear, well-spaced, and show an active state (orange underline or highlight) for the current page.
The header should be fixed/sticky on scroll. It should not take up too much vertical space — data density matters.


SECTION 2: GLOBAL UX IMPROVEMENTS
These apply across the entire app, not to any single tool.
2.1 Loading States
Every data-dependent component should have a proper loading state. No blank screens while data loads. Use skeleton loaders (gray shimmer rectangles in the shape of the content) or a minimal spinner. Match the design system.
2.2 Transitions & Micro-Animations
Add subtle transitions throughout the app. Nothing flashy. Just polish:

Page transitions: slight fade or slide when switching between tools
Card hover: cards should have a subtle lift effect (slight scale + shadow change) on hover. Not dramatic — 1-2px translate and a slightly stronger shadow. This applies to stock cards on The Stack, facility cards on the Power Map, index cards on Tilt Overview.
Number changes: when live prices or index values update, the number should briefly flash or color-pulse (green flash for increase, red for decrease) then settle. Not a full animation — a 200-300ms color transition.
Tab/filter selection: smooth transition when switching views, selecting filters, toggling modes.
Tooltips: should fade in, not pop. 150ms transition.

2.3 Hover States (Global)
Everything that's interactive should have a visible hover state:

Buttons: slight color shift or brightness change
Stock tickers on The Stack: row highlight on hover, maybe slight left-border color accent
Map pins on Power Map: see Section 4 for detailed hover behavior
Links: color change on hover
Cards: lift effect as described above
Index cards on Tilt Overview: hover should show a subtle border glow or accent

2.4 Responsive Polish
Go through every tool on a mobile viewport (375px width). Fix anything that breaks, overflows, or looks cramped. Specific things to check:

The Stack table: does it scroll horizontally properly? Are columns prioritized (ticker and price always visible, less important columns scroll)?
Power Map: is it usable on mobile? Can you tap pins and see details?
Thesis Calculator: do the inputs stack properly? Are sliders usable on touch?
Navigation: should collapse to a hamburger or bottom tab bar on mobile.

2.5 Footer
Add a clean, minimal footer to every page:

Left: "GridTilt © 2026 — Power-grid data, at a glance."
Right: Links to "About" (can be a simple modal for now), "X/Twitter" (@gridtilt), methodology page
Keep it very simple. One line. Muted colors.

By grid region/RTO: PJM, MISO, ERCOT, WECC, SERC, SPP, NPCC. Multi-select. Counts next to each.
By capacity range: <100 MW, 100-500 MW, 500+ MW. Or a range slider.

When filters are applied:

Filtered-out pins should fade to ~15% opacity (not disappear entirely — users should still see the full landscape but with filtered pins highlighted)

Mobile matters. Test every change on a 375px viewport before calling it done.
Performance matters. Don't add animations or effects that cause jank. Everything should be GPU-accelerated CSS (transform, opacity) where possible.
Data gaps are okay. If some facilities don't have operator info or MW capacity, use "Unknown" or "TBD." Don't let missing data block the build.
Ask before deciding. If you're choosing between two approaches and neither is clearly better, ask me. Don't guess.
No placeholder content in production. If a feature needs real data I haven't provided yet (like catalyst events or news headlines), build the component and wire it to a simple data source I can edit, then leave a clear comment telling me how to add content.
